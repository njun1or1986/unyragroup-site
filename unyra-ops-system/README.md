# UNYRA Ops System

This layer is the founder-facing operating system for UNYRA GROUP LLC.

It is designed to let the founder move across sales, purchasing, logistics, compliance, SOPs, dashboards, and archives through one governed structure without losing control of master templates or live source records.

## System discipline

| Discipline | Required behavior |
| --- | --- |
| Template custody | `01_templates/` holds protected master files. |
| Live-work boundary | Live work never happens inside `01_templates/`. |
| Working-copy control | For any active transaction, duplicate the right master template, rename it for the deal or shipment, and save the working copy in the correct live folder. |
| Dashboard boundary | Dashboards summarize source records; they do not replace the accountable room, packet, shipment, claim, or approval record. |
| Archive release | Archive only after closeout is real, retrieval is explicit, and the active layer no longer owns follow-through. |

## Daily Founder Workflow

1. Open `06_dashboard/01_executive/Daily-Founder-Dashboard.md`.
2. If the issue is cross-functional or unclear, open `06_dashboard/33_control-routing/Founder-Control-Routing-Matrix.md` before diving into a secondary review.
3. If the issue is important but the inputs may still be stale or uneven, open `06_dashboard/34_control-integrity/Executive-Control-Integrity-and-Decision-Readiness-Review.md` before making the call.
4. If a trust-linked executable check is active, same-day critical, fragmented across task, gate, review, and archive layers, or already in live-gate containment mode, open `06_dashboard/40_executable-checks/Trust-Override-Executable-Check-Control-Board.md` before widening any release or payment logic, then refresh `06_dashboard/25_scenario-response/Executive-Scenario-and-Contingency-Review.md` and `06_dashboard/18_executive-risk-register/Executive-Risk-Register.md` before treating the movement as controlled.
5. Review active deals in `02_crm/04_deals/active/`.
6. Review active shipments in `03_operations/03_shipments/active/`.
7. Check urgent compliance items in `04_compliance/`.
8. When a new transaction starts, copy the right master file from `01_templates/`.
9. Rename the copy with the date, company, document type, and version.
10. Save the live file in the correct operational folder, not in the templates folder.
11. If the live matter is under contained movement, make sure outward-facing source documents like proforma, contract, purchase order, shipping instructions, and packet documents repeat the same current stop rule and next safe movement carried by the linked controls.
12. Update dashboards only after source records are current.
13. Prepare a closeout record for meaningful completed matters.
14. If a trust-linked executable check was used, preserve its closure evidence in the packet, review, and closeout path before archive.
15. Move completed material to `07_archive/` once the matter is fully closed.
16. Use the generated `.html` companion views when you want founder-friendly reading and presentation quality.

## Weekly Founder Workflow

1. Update the daily dashboards and source records first.
2. Open `06_dashboard/14_weekly-executive-review/Weekly-Executive-Operating-Review.md`.
3. Review weekly movement across sales, operations, compliance, cash, and founder decisions.
4. If cash, release, or supplier capacity is constrained, open the capital allocation review before approving more acceleration.
5. If one downside trigger could materially change posture, refresh the scenario and contingency review before the week closes.
6. If the week is still leaning on unproven assumptions, refresh the assumption and dependency review before calling the posture clean.
7. If quarter commitments are drifting, refresh the plan variance and recovery review before calling the week acceptable.
8. If the same strategic issue still needs repeated founder rescue, refresh the owner accountability review before accepting the owner path.
9. If a trust-linked founder override reaches the live gate stage, open or update a task record for the executable check instead of leaving it as a dashboard-only reminder.
10. If more than one executable check is active, if closure proof is fragmented across task, gate, review, and archive layers, or if any trust-linked gate failure still needed same-day containment, open `06_dashboard/40_executable-checks/Trust-Override-Executable-Check-Control-Board.md`, then confirm `06_dashboard/25_scenario-response/Executive-Scenario-and-Contingency-Review.md` and `06_dashboard/18_executive-risk-register/Executive-Risk-Register.md` still carry the same contained-movement answer before treating the week as controlled.
11. Set the top three priorities for the next week.
12. Convert any unresolved executive issue into a founder decision register or matter control update.

## Monthly Founder Workflow

1. Complete the weekly reviews for the month first, refresh the strategic counterparty trust review where relationship friction is becoming material, and refresh the adoption board when founder rescue or same-day gate discipline is still shaping the month.
2. Open `06_dashboard/15_monthly-strategic-review/Monthly-Strategic-Business-Review.md`.
3. Review business quality across growth, execution, counterparty response quality, compliance, cash, and profitability.
4. Open `06_dashboard/35_system-adoption/Operating-System-Adoption-and-Readiness-Board.md` when the month still contains repeated founder rescue, uneven control usage, or weak executable-check discipline.
5. Decide the top three priorities for the next month.
6. Open or update `06_dashboard/16_strategic-initiatives/Strategic-Initiative-Tracker.md` for any priority that should stay alive across the month.
7. Record any cross-functional strategic decision in the relevant founder decision register or matter control record.

## Counterparty Trust Workflow

1. Refresh the communication control board, response escalation board, customer account review board, supplier performance review board, and linked deal, shipment, customer, or supplier records first.
2. Open `06_dashboard/38_counterparty-trust/Strategic-Counterparty-Trust-and-Response-Review.md`.
3. Judge whether strategic counterparties are responding with dependable acknowledgment quality, manageable escalation burden, and low-friction follow-through.
4. Open `06_dashboard/39_trust-posture/Counterparty-Trust-Tier-and-Release-Posture-Matrix.md` when trust quality should change release posture, growth pace, or sourcing confidence.
5. Assign an explicit trust tier and operating consequence instead of leaving the conclusion as narrative-only watch language.
6. If the founder decides to proceed despite fragile or only controlled trust posture, capture that move in the founder decision register and exception review as a bounded override with explicit blocked actions, recheck timing, and return-to-standard proof.
7. Push any material conclusion into the monthly review, quarterly plan, executive KPI scorecard, executive risk register, or founder decision register.

## Quarterly Founder Workflow

1. Refresh the monthly strategic review, strategic counterparty trust review, communication control board, response escalation board, initiative tracker, revenue forecast, capital allocation review, scenario response review, assumption review, plan variance review, KPI scorecard, risk register, cash forecast, concentration review, and supply resilience review first.
2. Open `06_dashboard/22_quarterly-operating-plan/Quarterly-Operating-Plan.md`.
3. Convert strategy into quarter targets, named owners, explicit trade-offs, strategic response-discipline commitments on key counterparties, and live-gate discipline commitments where founder rescue is still too common.
4. Use the plan to define what must be true by quarter end, not just what feels important right now.
5. Push the quarter priorities back into the initiative tracker, founder decisions, and functional reviews, especially when a quarter commitment depends on better executable-check behavior.

## Revenue Forecast Workflow

1. Refresh the sales pipeline command center, pricing governance board, internal deal summaries, and quarterly operating plan first.
2. Open `06_dashboard/23_revenue-forecast/Revenue-Forecast-and-Commitments-Review.md`.
3. Separate committed revenue from high-confidence, weighted, and stretch revenue.
4. Treat slippage risk as a founder decision problem early, not after forecast miss happens.
5. Tighten quote discipline or forecast bands whenever confidence is overstated.

## Capital Allocation Workflow

1. Refresh the cash forecast, revenue forecast, funding release review, credit and release control, strategic counterparty trust review, trust posture matrix, supplier capacity review, quarterly operating plan, and executive risk register first.
2. Open `06_dashboard/24_capital-allocation/Capital-Allocation-and-Release-Priority-Review.md`.
3. Decide where scarce cash, supplier capacity, trust-weighted release confidence, and founder approvals should go first.
4. Hold or defer lower-confidence or weaker-trust matters before they consume working capital and override attention.
5. Convert any material allocation choice into linked founder decisions, matter control updates, trust-linked release conditions, or payment gates.

## Scenario Response Workflow

1. Refresh the executive risk register, cash forecast, capital allocation review, concentration review, supply resilience review, quarterly operating plan, operating-system adoption board, and executable-check control board first.
2. Open `06_dashboard/25_scenario-response/Executive-Scenario-and-Contingency-Review.md`.
3. Define the trigger, the first 48-hour response, the fallback path, and the decision owner for each material downside scenario, including trust-linked live-gate failure.
4. Pre-decide what gets frozen, downgraded, accelerated, or escalated before pressure creates improvisation or founder rescue.
5. Link each critical scenario to founder decisions, matter control, release conditions, or communication steps where needed.

## Assumption Control Workflow

1. Refresh the quarterly operating plan, revenue forecast, scenario response review, cash forecast, capital allocation review, operating-system adoption board, executable-check control board, and linked source records first.
2. Open `06_dashboard/26_assumption-control/Executive-Assumption-and-Dependency-Review.md`.
3. Name the assumptions, timing dependencies, and trust-linked live-gate behaviors that the current plan is relying on.
4. Give each one a proof date, a failure trigger, and a fallback path before treating it as reliable.
5. Tighten plan posture whenever key assumptions remain fragile, late, or too dependent on founder rescue at live gates.

## Plan Variance Workflow

1. Refresh the quarterly operating plan, strategic initiative tracker, operating-system adoption board, executable-check control board, weekly review, monthly review, executive KPI scorecard, assumption review, and linked source records first.
2. Open `06_dashboard/27_plan-variance/Executive-Plan-Variance-and-Recovery-Review.md`.
3. Compare actual movement against the quarter priorities, milestone map, functional commitments, and trust-linked live-gate behavior.
4. Name the variance, the root cause, the recovery move, and the proof window before calling the quarter on track.
5. Escalate any repeated founder-rescued variance into an executable-check record, recovery record, founder decision, or initiative reset instead of hiding it in status language.

## Owner Accountability Workflow

1. Refresh the executive decision board, strategic initiative tracker, plan variance review, executive risk register, weekly review, monthly review, and linked source records first.
2. Open `06_dashboard/28_owner-accountability/Executive-Owner-Accountability-and-Follow-Through-Review.md`.
3. Test whether named owners are actually delivering the commitments they already own.
4. Separate true owner execution from motion that still depends on repeated founder rescue or vague escalation.
5. Tighten owner paths, deadlines, and escalation quality before assuming another dashboard or another meeting will solve the problem.

## Executive Scorecard Workflow

1. Refresh the daily, weekly, monthly, communication control, response escalation, strategic counterparty trust review, and initiative layers first.
2. Open `06_dashboard/17_executive-kpi-scorecard/Executive-KPI-Scorecard.md`.
3. Check score confidence and refresh integrity before trusting the read.
4. Read the business through normalized KPI quality, not only through unqualified activity, including counterparty trust and response reliability.
5. Use the scorecard to decide where founder pressure should increase, not to replace the underlying source records.

## Executive Risk Workflow

1. Refresh the weekly review, monthly review, communication control board, response escalation board, strategic counterparty trust review, executive scenario and contingency review, and executive KPI scorecard first.
2. Open `06_dashboard/18_executive-risk-register/Executive-Risk-Register.md`.
3. Rank which exposures are truly critical, worsening, or overdue.
4. Convert any unowned or cross-functional exposure, including trust or response breakdown on strategic counterparties and any live-gate failure still leaning on founder rescue, into a founder decision register or matter control update.
5. Use the register to decide where mitigation ownership and escalation timing must tighten next.

## Cash Forecast Workflow

1. Refresh collections control, credit and release control, funding and payables release review, trade profitability, and the executive risk register first.
2. Open `06_dashboard/19_cash-forecast/Cash-Forecast-and-Exposure-Outlook.md`.
3. Judge whether expected cash timing is real enough to support current release and growth posture.
4. Treat release-dependent inflows and downside scenarios as founder timing decisions, not passive notes.
5. Tighten collection pressure, release discipline, or pricing exceptions whenever the outlook weakens.

## Funding Release Workflow

1. Refresh the cash forecast, capital allocation review, operations command center, shipment control tower, credit and release control, and linked shipment or deal records first.
2. Open `06_dashboard/29_funding-release/Funding-and-Payables-Release-Review.md`.
3. Decide which supplier, freight, broker, duty, or other outgoing payments are truly release-ready.
4. Hold any payment that lacks clean packet logic, filing readiness, or real cash coverage.
5. Treat outgoing cash discipline as part of founder release control, not as a back-office afterthought.

## Claims Recovery Workflow

1. Refresh complaint forms, customer account review, trade profitability review, shipment review logs, supplier performance review, and linked source records first.
2. Open `06_dashboard/30_claims-recovery/Claims-Credits-and-Recovery-Review.md`.
3. Decide the customer remedy, supplier recovery path, and economic impact together, not in separate tracks.
4. Prevent credits or replacements from becoming uncontrolled margin leakage.
5. Close the case only after customer recovery, supplier recovery, and profitability impact are all reflected in the system.

## CAPA Governance Workflow

1. Refresh complaint forms, inspection records, claims recovery review, shipment review logs, supplier performance review, and linked source records first.
2. Open `06_dashboard/31_capa-governance/CAPA-and-Preventive-Action-Review.md`.
3. Judge whether containment, root-cause logic, corrective action, and preventive action are all strong enough to trust.
4. Do not let a case close just because the immediate issue was contained.
5. Treat CAPA verification and recurrence prevention as founder-level control, not as a buried compliance note.

## Exception Governance Workflow

1. Refresh pricing governance, credit and release control, funding and payables release review, claims recovery review, CAPA review, founder decision board, and linked source records first.
2. Open `06_dashboard/32_exception-governance/Executive-Exceptions-and-Override-Review.md`.
3. Judge whether temporary deviations are still justified, still bounded, and still reversible.
4. Add expiry logic and recovery paths before approving any new exception cluster.
5. Treat exception stacking as a sign of control drift, not as proof that the business is being flexible.

## Control Routing Workflow

1. Refresh the founder dashboard, executive decision board, matter control index, and linked functional reviews first.
2. Open `06_dashboard/33_control-routing/Founder-Control-Routing-Matrix.md`.
3. Decide which control layer should lead the issue before starting a founder call or escalation path.
4. Use the routing matrix when one issue could be mistaken for a sales problem, an ops problem, or a compliance problem depending on who is speaking first.
5. If a trust-linked founder override is active, route it in this order: sync the override meaning, confirm decision-readiness in control integrity, and, if the gate has already entered failure-containment mode, route through executable-check control, scenario response, and executive risk before reopening the live functional gate.
6. Treat clean routing as an executive control function, not as admin.

## Control Integrity Workflow

1. Refresh the founder dashboard, executive KPI scorecard, executive risk register, control routing matrix, and linked functional reviews first.
2. Open `06_dashboard/34_control-integrity/Executive-Control-Integrity-and-Decision-Readiness-Review.md`.
3. Decide whether the system is actually current enough to support the founder call you are about to make.
4. Treat any provisional, stale, or weak linked layer as a reason to refresh, not as a reason to guess.
5. If a trust-linked founder override is active, confirm the founder decision register, trust posture matrix, matter control index, executable-check board, scenario response review, executive risk register, and linked release-use controls all carry the same override and containment logic before treating the matter as executable.
6. Use this review whenever a matter looks polished but may still be incomplete across linked controls.

## System Adoption Workflow

1. Refresh the founder dashboard, control routing matrix, control integrity review, owner accountability review, and linked functional dashboards first.
2. Open `06_dashboard/35_system-adoption/Operating-System-Adoption-and-Readiness-Board.md`.
3. Judge whether the system is being used as a real operating behavior, not just as a well-designed repository.
4. Treat repeated off-system decisions, weak closeout discipline, or fragile naming habits as adoption issues, not minor admin gaps.
5. Use this review monthly until the system feels strong without heavy founder forcing.

## Concentration Workflow

1. Refresh customer account review, supplier performance, profitability review, cash forecast, and executive risk layers first.
2. Open `06_dashboard/20_concentration-risk/Portfolio-Concentration-Review.md`.
3. Judge whether revenue, sourcing, product mix, or cash timing are becoming too dependent on a narrow cluster.
4. Use the review to set diversification priorities before concentration turns into fragility.
5. Convert any strategic concentration concern into sourcing, sales, pricing, or founder-priority action.

## Supply Resilience Workflow

1. Refresh supplier approval, supplier performance, shipment review, concentration review, and executive risk layers first.
2. Open `06_dashboard/21_supply-resilience/Supplier-Capacity-and-Backup-Sourcing-Review.md`.
3. Judge whether approved supply can actually hold under scale, disruption, or sudden demand pressure.
4. Treat backup-source readiness as a founder resilience decision, not just a sourcing note.
5. Accelerate fallback qualification whenever strong current execution is masking fragile capacity concentration.

## External Communication Workflow

1. Confirm the source commercial, operational, legal, or compliance records are current first.
2. Open the relevant live folder for the deal, shipment, customer, or supplier.
3. Prepare `Official-Document-Transmittal`, `Institutional-Trade-Correspondence`, and `Counterparty-Document-Packet-Index` as needed.
4. Complete `External-Communication-Release-Checklist` before sending.
5. Make sure the outgoing packet reads like a disciplined institution, not an improvised attachment dump.
6. Save the final communication set back into the live folder so UNYRA retains release evidence.
7. If multiple formal communications are active at once, update `06_dashboard/36_external-communications/Counterparty-Communication-Control-Board.md`.
8. Use the institutional communication style guide and message framework before finalizing important customer or supplier wording.
9. If the response timing matters commercially or operationally, update `06_dashboard/37_response-escalation/Counterparty-Response-SLA-and-Escalation-Board.md`.
10. If the linked matter is already in contained movement, make sure the outward wording matches the executable-check board, scenario response review, executive risk register, and the live funding or release gate before sending.

## Operating Lifecycle

### Lifecycle playbooks

| Playbook | Use |
| --- | --- |
| `05_sops/04_crm/Commercial-Execution-Lifecycle-SOP.md` | Govern lead, customer, supplier, deal, and execution transitions. |
| `05_sops/07_archive/Archive-Closeout-SOP.md` | Govern controlled closeout and archive release. |

### Intended flow

1. Lead
2. Customer or supplier onboarding
3. Deal
4. Offer and contract cycle
5. Purchasing and shipment execution
6. Compliance filings and evidence
7. Complaint or CAPA if needed
8. Controlled closeout and archive release
9. Archive only after full closure

This keeps the repository sequential and founder-readable, instead of mixing early-stage leads with live execution files.
