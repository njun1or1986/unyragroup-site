# Counterparty Communication Standard SOP

| SOP control | Current standard |
| --- | --- |
| Status | ACTIVE SOP |
| Purpose | Define how UNYRA should communicate with customers, suppliers, and other external counterparties so every controlled release feels consistent, premium, and institution-grade. |
| Source rule | Use the approved external-communication templates, institutional language guide, communication control board, response SLA, trust posture matrix, executable-check board, scenario response review, executive risk register, and linked live matter records before any high-stakes outward message is finalized. |
| Decision rule | Do not let counterparty-facing wording outrun the internal control answer; every release, payment, shipment, claim, pricing, trust, or containment statement must match the current governed posture. |
| Template protection | Reference and use the protected master templates as issued; improve live communication records and packet discipline without editing approved template masters during SOP polish. |

## 1. Communication Principle

Every external document sent by UNYRA should feel like it came from a disciplined institution, not from an improvised back-office workflow.

The standard is defined by these required signals.

| Communication standard | Required signal |
| --- | --- |
| Control | The message shows that UNYRA knows the governing record, gate, owner, and next action. |
| Clarity | The recipient can understand the purpose, action requested, deadline, and linked matter without guessing. |
| Accountability | The sender, owner, and expected response path are explicit. |
| Premium brand discipline | The communication uses approved institutional tone, structure, and brand closure. |
| Confidence in execution | The message reads as decision-ready, not improvised or reactive. |

## 2. Mandatory Institutional Minimum

Every formal customer or supplier communication should clearly show the following minimum fields.

| Field | Required use |
| --- | --- |
| UNYRA brand masthead | Identifies the communication as institution-grade UNYRA output. |
| Document or communication reference number | Gives the release a controlled identifier. |
| Issue date | Confirms the timing of the outward position. |
| Sender name and role | Shows who owns the message. |
| Recipient name and company | Confirms the counterparty and intended audience. |
| Subject or purpose | States why the communication exists. |
| Linked deal, shipment, or control reference | Connects the message to the accountable record when relevant. |
| Exact action required | Makes the recipient's next move explicit. |
| Response deadline | Defines timing when response behavior matters. |

Do not send important counterparty communication without those basic fields.

## 4. When To Use Which Format

### One formal message, request, or notice

Use institutional trade correspondence.

Standard examples are listed below.

| Example use | Format |
| --- | --- |
| Request for confirmation | Institutional trade correspondence. |
| Controlled clarification | Institutional trade correspondence. |
| Delivery or release notice | Institutional trade correspondence. |
| Document deficiency notice | Institutional trade correspondence. |
| Deadline reminder | Institutional trade correspondence. |
| Formal acknowledgment | Institutional trade correspondence. |

### One packet with multiple files

Use all of the following packet controls together.

| Packet component | Required role |
| --- | --- |
| Official document transmittal | Identifies the release and the controlled packet being sent. |
| Packet index | Lists every enclosed controlled file and revision. |
| Release checklist | Confirms the packet is ready to leave UNYRA. |

If the packet touches a contained payment, release, shipment, or handoff posture, complete the movement-posture, stop-rule, next-safe-movement, and revalidation fields in those documents before sending.

### Sensitive or high-stakes release

If the release affects price, payment, delivery timing, claims position, compliance posture, or legal exposure:

| Release control | Required behavior |
| --- | --- |
| Checklist first | Complete the release checklist before the message leaves UNYRA. |
| Linked record | Link the communication to the correct deal, shipment, compliance, or founder-decision record. |
| Version control | Confirm the outgoing files are the latest controlled versions. |
| Containment alignment | If the underlying movement is in containment mode, confirm the outward wording matches the executable-check board, scenario response review, executive risk register, and the live gate before sending. |

## 5. Tone Standard

Counterparty communication should carry the following tone attributes.

| Tone attribute | Required expression |
| --- | --- |
| Formal | Uses business-grade language suitable for banks, customs teams, procurement offices, and executive inboxes. |
| Concise | States the matter, request, deadline, and owner without unnecessary narrative. |
| Explicit | Makes the required action and consequence of delay clear. |
| Respectful | Keeps the wording disciplined even when the counterparty is late, incomplete, or difficult. |
| Commercially clear | Protects price, payment, delivery, claim, compliance, and release posture from ambiguity. |

Avoid the following patterns because they weaken control.

| Pattern to avoid | Why it weakens control |
| --- | --- |
| Chat-style wording | Makes the communication feel informal and harder to archive as a controlled record. |
| Vague promises | Creates expectation risk without a committed gate, owner, or date. |
| Emotional language | Weakens institutional tone and can escalate tension unnecessarily. |
| Slang | Reduces premium credibility and creates forwarding risk. |
| Inconsistent capitalization | Makes the communication feel unreviewed. |
| Long unstructured paragraphs | Hides the request, deadline, and accountable record. |

Write like UNYRA expects the message to be forwarded inside a bank, customs team, procurement office, or executive inbox.

Use `00_brand/02_guidelines/UNYRA-Institutional-Communication-Style-Guide.md` as the language source of truth when drafting.

## 6. Packet Discipline

When multiple files are sent, the packet should identify the following fields.

| Packet discipline field | Required answer |
| --- | --- |
| Enclosures | Exactly what is enclosed. |
| Revision control | The revision of each controlled file. |
| Counterparty action | What action the recipient should take. |
| Response deadline | The next required response date or time. |
| UNYRA owner | Who owns follow-through after release. |
| Movement posture | The current stop rule and next safe movement if the packet touches a constrained release or payment posture. |
| Hold or revalidation status | What remains on hold or under revalidation if the movement is not yet fully cleared. |

Do not make the recipient guess which attachment matters most.

## 8. Storage Rule

Store the working communication set in the live folder that owns the matter.

| Matter type | Storage location |
| --- | --- |
| Commercial release | Active deal folder. |
| Logistics or release communication | Shipment folder. |
| Onboarding or account communication | Customer folder. |
| Qualification or sourcing communication | Supplier folder. |

Do not bury key external releases only in email.

The repository should retain the evidence of what UNYRA sent, why it was sent, and what response was expected.

## 9. Release Gate Rule

Before a formal release goes out, complete the following gate steps.

| Gate step | Required action |
| --- | --- |
| 1 | Confirm the correct source documents are current. |
| 2 | Complete the release checklist. |
| 3 | Confirm the right template is being used. |
| 4 | Confirm naming, references, and recipient details. |
| 5 | Save the communication record back into the live folder after sending. |

## 10. Signature and Brand Rule

Use approved UNYRA signatures and compositions only.

Do not create improvised email footer art, stretched logos, or alternate lockups.

Use the approved founder or business-development signature assets from `00_brand/01_assets/04_signatures/` when a visual signature block is needed.

## 11. Escalation Rule

If the outgoing communication commits UNYRA on any of the following areas, the communication should reference the linked internal control record before it is treated as final:

| Commitment area | Required control posture |
| --- | --- |
| Pricing | Confirm the commercial source record and approval path. |
| Payment timing | Confirm the funding, payables, or collections control answer. |
| Shipment release | Confirm the live shipment, release gate, and movement posture. |
| Compliance posture | Confirm the compliance record and any review or release condition. |
| Claim remedy | Confirm the claim, credit, recovery, or remedy control record. |
| Exception approval | Confirm the founder-decision or exception-approval record. |

If the outward message could be read as widening a contained payment or release posture, it should also reference the current movement posture and must not imply broader clearance than the gate allows.

## 12. Communication Control Rule

When multiple formal communications are live at the same time, or when silence from a customer or supplier is becoming material:

| Control action | Required behavior |
| --- | --- |
| Open the control layer | Use the counterparty communication control register or board. |
| Track the release | Record what was sent and when it was sent. |
| Track the response | Record what response is due and by when. |
| Define escalation | State the escalation trigger explicitly. |
| Assign ownership | Assign one internal owner for follow-through. |

Do not let institution-grade outbound communication collapse into inbox memory.

## 13. Response SLA Rule

For important formal communication, define the response SLA before the message goes out.

For response-SLA discipline, define the following answers before release.

| SLA decision | Required answer |
| --- | --- |
| Receipt confirmation | When receipt confirmation is expected. |
| Full response | When the full response is expected. |
| First reminder | When the first reminder goes out. |
| Escalation trigger | When silence becomes escalation. |
| Hold or revalidation trigger | When a hold, revalidation, or founder escalation should occur. |

Use `01_templates/11_external-communications/Counterparty-Response-SLA-and-Escalation-MASTER.md` when the response window matters commercially or operationally.

## 14. Containment Communication Rule

When a customer, supplier, broker, or forwarder is being updated on a matter already in containment mode:

| Containment step | Required behavior |
| --- | --- |
| Open the control board | Use the communication control board before outward wording is finalized. |
| Reconfirm live answer | Confirm the executable-check board, scenario response review, executive risk register, and linked funding or release gate still carry the same answer. |
| State only the current posture | Communicate only the current controlled posture, the required next counterparty action, and the next safe movement if one is allowed. |
| Avoid premature release language | Do not describe the matter as fully released, fully approved, or clear to proceed unless the live gate has actually moved to that posture. |

Do not let outward wording outrun the internal control answer.

## 15. Strategic Trust Review Rule

When a customer or supplier is strategically important and response behavior itself starts affecting release confidence, cash timing, account posture, or sourcing confidence:

| Trust-review action | Required behavior |
| --- | --- |
| Open the strategic review | Use `06_dashboard/38_counterparty-trust/Strategic-Counterparty-Trust-and-Response-Review.md`. |
| Judge behavior quality | Review acknowledgment quality, escalation frequency, and repeat response friction over time. |
| Decide relationship posture | Decide whether UNYRA should keep scaling the relationship, tighten release posture, or build more fallback protection. |
| Carry the conclusion | Move any material conclusion into the customer account review, supplier performance review, monthly strategic review, KPI scorecard, and executive risk register. |

Do not treat repeated silence on important matters as only an inbox problem. Treat it as relationship-quality evidence.

## 16. Trust Tier and Release Posture Rule

When the strategic trust review shows that relationship behavior should change how UNYRA releases, grows, sources, or escalates:

| Posture action | Required behavior |
| --- | --- |
| Open the matrix | Use `06_dashboard/39_trust-posture/Counterparty-Trust-Tier-and-Release-Posture-Matrix.md`. |
| Assign trust tier | Set an explicit trust tier instead of using only descriptive watch language. |
| Define operating posture | Define the matching release posture, growth pace, or sourcing fallback rule. |
| Refresh linked controls | Update any linked credit, release, capital allocation, or supply resilience control that should carry the posture. |
| Carry material impact | Move material conclusions into the founder dashboard, monthly review, and quarter planning. |

Do not leave a strategic counterparty on "watch" without saying what that watch changes operationally.
