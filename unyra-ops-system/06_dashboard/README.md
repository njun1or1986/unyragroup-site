# 06 Dashboard

This layer is the founder cockpit for UNYRA. It summarizes live posture across commercial, operations, compliance, cash, supplier, risk, release, owner, adoption, and strategic-control surfaces without replacing the source rooms that still own action, evidence, and final record custody.

## Dashboard Control Posture

| Control Field | Current Standard | Founder Use |
| --- | --- | --- |
| Layer status | Active founder control and decision-readiness layer | Use dashboards to see posture, tension, escalation, and next control route. |
| Primary purpose | Convert source records into founder-readable intervention, cadence, risk, and gate-control views. | Gives the founder a cockpit without turning dashboards into working files. |
| Source rule | Update CRM, operations, compliance, archive, SOP, shipment, task, and source rooms first, then refresh dashboards. | Prevents polished dashboards from outrunning the records that own proof. |
| Decision rule | Founder decisions must trace back to the live room, board, packet, claim, shipment, task, or owner record that holds evidence. | Keeps approvals, releases, and exceptions route-backed. |
| Protection rule | Dashboards may summarize protected template standards but must not mutate protected template masters or approved brand assets. | Preserves template and brand integrity while dashboard views evolve. |

## Source Ownership Standard

| Dashboard Use | Source Room Still Owns | Required Founder Behavior |
| --- | --- | --- |
| Summary posture | CRM, operations, compliance, archive, SOP, shipment, task, or template-protected source records. | Treat dashboard status as a readout, not a substitute for the source record. |
| Release or gate decision | Release room, funding room, document-control packet, executable-check board, and trust posture record. | Confirm executable proof before movement widens. |
| Commercial confidence | Lead, customer, supplier, active deal, won deal, lost deal, pricing, cash, and revenue records. | Keep forecast and commercial banding tied to source proof. |
| Compliance confidence | Traceability, complaint, CAPA, inspection, supplier approval, and shipment-review records. | Keep closure language bounded until evidence agrees. |
| Archive confidence | Active source record and archive closeout route. | Do not archive while any live source answer can still change. |

## Dashboard Discipline

| Discipline | Required Behavior | Escalation Trigger |
| --- | --- | --- |
| Evidence ownership | Dashboards summarize linked records; they do not replace rooms, packets, claims, shipments, approvals, or task records. | Any dashboard becomes the only place where status, owner, or proof exists. |
| Decision traceability | Any release, override, archive, capital, supplier, or communication decision should trace back to the accountable source record. | Founder approval is requested from a dashboard alone. |
| Founder control surface | Dashboards are decision-readiness surfaces, not loose operating storage. | Working files, drafts, or proof packets appear inside dashboard folders. |
| Template and brand protection | Dashboards may link to approved standards but should not change protected template masters or approved brand assets. | Dashboard cleanup touches `01_templates/` or approved brand compositions. |
| Cadence integrity | Daily, weekly, monthly, and quarterly surfaces should answer different time horizons. | Same-day pressure starts rewriting quarterly direction without the plan and assumption boards. |
