# UNYRA Institutional Communication Style Guide

This guide defines how UNYRA GROUP LLC should sound when communicating with customers, suppliers, brokers, forwarders, banks, customs-related parties, and other external counterparties.

The goal is not only to look premium, but to read with the consistency and authority of a serious institution.

| Guide Control | Current Standard |
| --- | --- |
| Status | Active language standard |
| Purpose | Define the institutional tone, request language, deadline discipline, escalation wording, closing style, and containment language used in formal UNYRA counterparty communication. |
| Source rule | Use this guide with the protected external-communication templates, counterparty communication SOP, communication control board, response SLA, trust posture matrix, and live matter records before high-stakes outward wording is finalized. |
| Decision rule | Wording must stay as narrow as the live control answer; do not imply broader pricing, payment, release, shipment, claim, or approval posture than the current source records support. |
| Template protection | This guide governs language only; approved template masters and brand assets remain protected sources of truth. |

## 1. Communication Objective

Every important external message should communicate the following objectives.

| Objective | Required signal |
| --- | --- |
| Institutional control | The message makes the reference, owner, stage, and next action clear. |
| Commercial clarity | The recipient understands what is being requested, confirmed, released, rejected, or held. |
| Executive calm | The tone stays measured even when timing, risk, or counterparty behavior is difficult. |
| Operational precision | Dates, deadlines, references, files, and gates are specific. |
| Disciplined follow-through | The message shows who owns the next response and what happens if the response is delayed. |

The recipient should feel that UNYRA knows exactly what was sent, why it was sent, what happens next, and who owns the next step.

## 2. Tone Standard

| Tone to use | Tone to avoid |
| --- | --- |
| Formal | Casual |
| Concise | Overly friendly |
| Respectful | Apologetic without reason |
| Explicit | Vague |
| Measured | Chat-like |
| Internationally credible | Emotionally reactive |

## 3. Sentence Style

| Prefer | Avoid |
| --- | --- |
| Short paragraphs | Long winding explanations |
| Direct statements | Stacked questions in one paragraph |
| Clean request language | Passive wording when ownership matters |
| One clear action per sentence when possible | Filler phrases |
| Concrete deadlines | Open-ended timing language |

## 4. Subject Line Standard

Subject lines should be structured and scannable.

| Element | Standard |
| --- | --- |
| Preferred format | `[UNYRA Ref] Clear institutional subject` |
| Reference quality | Use the communication, matter, or release reference when available. |
| Subject quality | State the reason for the communication without casual wording. |

Subject-line examples are listed below.

| Example subject line | Use case |
| --- | --- |
| `[COMM-2026-041] Formal Offer Packet for Review and Confirmation` | Formal commercial release requiring review. |
| `[COMM-2026-044-L1] Final Shipment Alignment Confirmation Required` | Time-sensitive shipment confirmation. |
| `[COMM-2026-052] Document Deficiency Notice and Response Deadline` | Controlled deficiency notice with a response requirement. |

## 5. Opening Standard

Open with the following elements.

| Opening element | Required content |
| --- | --- |
| Reason for the message | State why UNYRA is writing. |
| Linked matter | Identify the deal, shipment, packet, payment, compliance, or control reference when relevant. |
| Response importance | State the response, confirmation, or action needed. |

Use this good opening pattern.

`UNYRA is issuing this communication in connection with [matter] to confirm [specific purpose].`

## 6. Action Request Standard

When asking for action, use verbs that sound controlled.

| Controlled verb | Appropriate use |
| --- | --- |
| Confirm | Receipt, position, timing, release, or status. |
| Review | Documents, terms, packet contents, or proposed next steps. |
| Approve | Formal authorization or acceptance. |
| Reject | Clear refusal or exception response. |
| Acknowledge | Receipt or awareness without implying full approval. |
| Provide | Missing documents, evidence, instructions, or payment proof. |
| Return | Signed documents, written responses, or completed forms. |
| Advise | A controlled response where the counterparty must provide direction. |

Do not hide the request in soft language.

Use this preferred request pattern.

`Please confirm receipt and return your written response by [date and time].`

## 7. Deadline Standard

| Deadline field | Required use |
| --- | --- |
| Exact due date | State the actual calendar date. |
| Time | Include the time when timing affects release, payment, shipment, compliance, or escalation posture. |
| Timezone | Include the timezone when parties may operate across markets. |

Use this preferred deadline pattern.

`Please provide your written response by [Month Day, Year], at [time] [timezone].`

Avoid vague timing unless the matter is genuinely non-urgent.

| Avoid | Reason |
| --- | --- |
| `as soon as possible` | It creates urgency without an accountable deadline. |
| `soon` | It is not operationally measurable. |
| `when convenient` | It weakens response discipline. |

## 8. Escalation Standard

When silence or delay has consequences, say so in controlled language.

| Escalation element | Required expression |
| --- | --- |
| Consequence | State what may need to be revalidated, held, escalated, or reapproved. |
| Tone | Sound firm and disciplined, not threatening. |
| Scope | Avoid implying a broader consequence than the live control record supports. |

Use this preferred escalation pattern.

`If confirmation is delayed beyond the stated deadline, UNYRA may need to revalidate pricing, release timing, or packet status.`

## 9. Closing Standard

Close with the following elements.

| Closing element | Required content |
| --- | --- |
| Return channel | Tell the recipient where or how to return the response. |
| Escalation contact | Include the contact when the matter is urgent or controlled. |
| Institutional closing line | Close cleanly without casual filler. |

Preferred closings are listed below.

| Preferred closing | Use case |
| --- | --- |
| `We appreciate your timely attention to this matter.` | General controlled close. |
| `Please return your response against the communication reference above.` | Reference-driven close. |
| `Should clarification be required, please contact the UNYRA owner identified in this release.` | Owner-driven close. |

## 10. Prohibited Language

Do not use language that sounds informal or weak in formal external releases.

| Avoid | Why it weakens the release |
| --- | --- |
| `just checking` | Sounds informal and non-controlled. |
| `friendly reminder` | Softens a formal response requirement. |
| `hope this helps` | Reads like casual support language. |
| `let me know` | Hides the specific requested action. |
| `whenever you can` | Removes deadline discipline. |
| `sorry to bother you` | Weakens authority without cause. |
| `quick question` | Frames a controlled matter as casual. |

## 11. Signature Rule

| Signature context | Language requirement |
| --- | --- |
| Founder signature | The body should sound founder-grade, controlled, and institutionally final. |
| Business-development signature | The body should still sound controlled, premium, and commercially precise. |
| Any approved UNYRA signature block | The wording should match the visual authority of the approved signature composition. |

## 13. Containment and Movement Language

When a deal, shipment, payment, or release path is under contained-movement control, apply these rules.

| Containment language rule | Required behavior |
| --- | --- |
| Current movement only | Describe only the movement that is actually current and allowed. |
| Held or revalidated items | State what remains under review, on hold, or subject to revalidation. |
| Linked internal control language | Use the same stop rule and next safe movement carried by the linked internal control records. |
| No broader release implication | Avoid wording that sounds broader, cleaner, or more final than the live gate actually allows. |

Use this preferred containment pattern.

`UNYRA is maintaining the matter under controlled review, and the next movement step will be reconfirmed against the current release conditions referenced above.`

Avoid when the executable-check board, scenario response review, executive risk register, funding review, or pre-shipment gate still carry a narrower answer:

| Avoid | Why it is unsafe |
| --- | --- |
| `the shipment is fully released` | Implies final shipment clearance. |
| `payment is clear to proceed` | Implies payment release authority. |
| `everything is approved` | Implies broader approval than the live gate may support. |
