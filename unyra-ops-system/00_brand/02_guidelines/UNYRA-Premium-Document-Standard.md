# UNYRA Premium Document Standard

This standard governs premium internal document design for UNYRA GROUP LLC.

It applies to dashboards, invoices, purchase documents, supplier approvals, intake sheets, and founder-facing rollups.

| Standard Control | Current Standard |
| --- | --- |
| Status | Active premium document standard |
| Purpose | Govern UNYRA's premium internal and founder-facing document design so operating records, dashboards, previews, and future PDF exports feel controlled, executive-ready, and institution-grade. |
| Source rule | Use the approved visual identity, approved compositions, exported visual standard, branded preview area, and institutional communication style guide before changing document hierarchy, layout, or outward-facing presentation. |
| Decision rule | Favor restrained structure, fast founder comprehension, source-record clarity, and approved brand usage over decorative redesign. |
| Asset protection | Do not redraw, stretch, recolor, restyle, or replace approved brand assets or protected template masters while applying this document standard. |

## 1. Visual Intent

Every document should communicate operational control, not decoration.

| Desired signal | Required expression |
| --- | --- |
| Premium | The layout feels deliberate, spacious, and finished. |
| Restrained | Visual emphasis is selective rather than loud. |
| Corporate | The document reads as suitable for executive, procurement, finance, and compliance review. |
| Internationally credible | The structure feels appropriate for cross-border trade and institutional counterparties. |
| Fast to scan | The important answer can be understood in under 30 seconds. |

## 2. Brand Source of Truth

Use the following approved brand assets first.

| Asset source | Required use |
| --- | --- |
| `00_brand/01_assets/05_approved-compositions/` | Use horizontal logo lockups and circular seal versions before creating any new composition. |
| `00_brand/01_assets/04_signatures/` | Use approved signature layouts for founder, business-development, or outbound signature treatment. |
| Approved compositions | Do not redraw, stretch, recolor, or restyle approved compositions without explicit approval. |

## 3. Color Roles

| Color role | Value | Use |
| --- | --- | --- |
| Primary navy | `#08121E` | Headers, titles, structure, and authority. |
| Support navy | `#102436` | Secondary framing and deep UI surfaces. |
| Gold accent | `#C2A071` | Accents, highlights, section rules, and positive emphasis. |
| Strong gold accent | `#9D7646` | Darker accent text or restrained premium emphasis. |
| Ivory | `#F7F3EC` | Soft premium backgrounds and document warmth. |
| Canvas | `#F3EEE6` | Background canvas and quiet surface contrast. |
| Muted text | `#5B6672` | Secondary information and supporting metadata. |
| Muted dark | `#2A3742` | Body copy, table detail, and secondary authority. |

Gold should be present, but restrained.

## 4. Typography Rules

| Typography rule | Required behavior |
| --- | --- |
| Data and operations | Use a crisp sans serif for data, tables, and operational content. |
| Document headers | Use larger, more spacious title styling for document headers and founder summaries. |
| Headings | Keep headings bold and short. |
| Micro-labels | Use uppercase micro-labels for metadata and section identifiers. |
| Density control | Avoid dense paragraphs when a list, table, or grid communicates faster. |

## 5. Layout Rules

| Layout rule | Required behavior |
| --- | --- |
| Margins | Use generous page margins. |
| Masthead | Keep the brand masthead compact. |
| Metadata | Group related metadata into clean cards or aligned detail rows. |
| Focal area | Use no more than one dominant focal area per page section. |
| Tables | Let tables breathe with clear row spacing and subtle dividers. |
| Section architecture | Prefer two or three strong sections over many small fragmented boxes. |

## 6. Dashboard Rules

| Dashboard rule | Required behavior |
| --- | --- |
| Founder answer first | Show the founder what matters first. |
| Decision hierarchy | Put priorities, KPIs, risks, next actions, and blockers before detailed logs. |
| Table discipline | Use concise tables with only the fields required for a decision. |
| Risk emphasis | Highlight risk or urgency with structure and contrast, not loud warning colors. |

## 7. Document Component Set

Preferred reusable components are listed below.

| Component | Use |
| --- | --- |
| Premium masthead | Establish brand authority without overpowering the document. |
| Metadata grid | Show owner, date, status, source, route, and control context. |
| KPI cards | Surface the few measures that change the decision. |
| Summary strip | Give the founder the fast reading before details. |
| Clean operational table | Organize source facts, gates, actions, and records. |
| Note panel | Contain important context without breaking the main flow. |
| Decision card | Isolate approval, blocker, exception, or founder-call requirements. |
| Approval or signature block | Close the document with accountable authority. |

Reuse the shared visual system in `00_brand/03_exports/01_visual-standard/`.

## 8. Print and Export Readiness

| Export rule | Required behavior |
| --- | --- |
| Screen and PDF quality | Previews should render well on screen and remain clean when printed to PDF. |
| Text protection | Avoid oversized background art behind critical text. |
| Closing placement | Keep signatures, totals, and approval blocks close to the end of each document. |
| Grayscale resilience | Maintain clear page hierarchy even in grayscale printouts. |

## 9. Approved Preview Area

Preview files live in `00_brand/03_exports/02_preview-docs/`.

| Preview use | Standard |
| --- | --- |
| Founder review | Use previews to evaluate visual quality before template or PDF upgrades. |
| Visual approval | Use previews as benchmark surfaces for the approved look and hierarchy. |
| Future PDF conversion | Keep previews clean enough to support later export workflows. |
| Future template upgrades | Use previews as design references, not as live operating source records. |

They are not source records for live operations.

## 10. External Communication Standard

Customer- and supplier-facing documents should feel like they came from a serious institution.

| External standard | Required expression |
| --- | --- |
| Header control | Use strong header control and clear brand placement. |
| Reference clarity | Include explicit subject and reference numbers. |
| Recipient clarity | Use clean recipient blocks. |
| Attachment discipline | Use disciplined attachment naming. |
| Action clarity | State clear action requests and deadlines. |
| Signature treatment | Use clean approved signature treatment. |
| Tone discipline | Avoid casual email styling. |
| Packet control | If multiple files are sent together, use a formal transmittal and packet index so the release feels controlled instead of improvised. |

The language should also follow `00_brand/02_guidelines/UNYRA-Institutional-Communication-Style-Guide.md` so the visual quality and wording quality stay aligned.
